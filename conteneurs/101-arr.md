## Fonctionnement

```
Seerr ─► Sonarr / Radarr ─► Prowlarr (indexeurs) ─┐
                    │                             ├─ via gluetun ─► Internet (ProtonVPN)
                    └──► qBittorrent ─────────────┘
qBittorrent écrit dans /data/downloads ; Sonarr/Radarr rangent dans /data/media (liens physiques)
Bazarr ajoute les sous-titres ; Plex (CT 100) lit /data/media
```

- Prévenir Plex après import : connexion *Settings → Connect → Plex Media Server* (hôte `192.168.1.100`, port `32400`, « Update Library ») active dans Radarr et Sonarr depuis le 07/10/2026 (authentification Plex.tv, jeton stocké dans la base de chaque appli). En plus de la surveillance des dossiers de Plex, voir [100-plex.md](100-plex.md).
- `FIREWALL_OUTBOUND_SUBNETS=192.168.1.0/24` : les *arr du LAN peuvent joindre Prowlarr/qBittorrent.
- Quand ProtonVPN attribue un port, gluetun lance `/gluetun/qbt-port.sh` qui le règle dans qBittorrent
  (copie : [config/ct101-arr/qbt-port.sh](../config/ct101-arr/qbt-port.sh)).
- Sauvegardes du compose : `docker-compose.yml.bak`, `docker-compose.yml.bak-cloudflared`.

## Supprimer un film

Sur l'hôte (en SSH, aussi depuis le téléphone via Tailscale `100.73.1.43`) :

```sh
supprimer-film "titre"          # demande confirmation
supprimer-film --test "titre"   # montre ce qui serait supprimé
```

Retire le film de Radarr avec ses fichiers (`/data/media`), puis supprime le torrent et son fichier dans qBittorrent (`/data/downloads`).
Script : `/usr/local/bin/supprimer-film` (source : [scripts/supprimer-film](../scripts/supprimer-film)).

## Quand une demande Seerr reste bloquée

Ni Seerr ni Radarr/Sonarr ne préviennent quand rien n'est trouvé. Depuis le 07/10/2026 :

- **Notifications du navigateur (Seerr, « Web Push »)** activées, et l'adresse publique
  `https://cine.bks-home.com` renseignée dans Seerr (liens des notifs). Chaque membre de la famille
  accepte les notifications sur le site (ou *Profil → Paramètres → Notifications → Web Push*) et reçoit
  « Disponible » / « Refusé » pour ses demandes. Sur iPhone : ajouter le site à l'écran d'accueil d'abord.
- **`films-introuvables`** (hôte, cron tous les jours à 18 h, `/etc/cron.d/films-introuvables`,
  journal `/var/log/films-introuvables.log`). Pour chaque demande approuvée depuis plus de 3 jours et
  toujours ni disponible ni en téléchargement : explique pourquoi (pas encore sorti en vidéo, avec la date ;
  aucun résultat chez les indexeurs ; ou résultats refusés avec le motif : qualité, sources, taille…),
  relance une recherche dans Radarr/Sonarr et envoie un message ntfy « Introuvable : titre » avec le nom
  de la personne qui a demandé. Au plus un rappel par semaine et par demande (`/var/lib/films-introuvables.json`).
  Sujet(s) ntfy : `/etc/films-introuvables.conf` (`NTFY_TOPICS=`, plusieurs séparés par des virgules,
  par exemple pour ajouter un sujet « famille »). Pour l'instant : le même sujet privé qu'Uptime Kuma.
  Essai sans rien envoyer : `films-introuvables --test`. Source : [scripts/films-introuvables](../scripts/films-introuvables).
- **Qualité :** Seerr envoie tout avec le profil « Ultra-HD » de Radarr et de Sonarr, qui accepte déjà du 720p au 4K
  (Radarr aussi le Bluray 480p/576p). La qualité n'est donc en général pas la cause d'un blocage. Les mises à niveau
  sont désactivées : un film pris en 1080p n'est pas re-téléchargé en 4K plus tard.
